# Допущения и решения по неоднозначностям

Журнал решений координатора. Каждое допущение по возможности вынесено в конфигурацию.

| # | Неоднозначность | Решение | Где настраивается |
|---|---|---|---|
| A1 | Шкала оценок: в исходной формулировке границы пересекаются на 60 («0–60 неуд», «60–70 удовл») | Как в ТЗ §14.1: **0–59 — неудовлетворительно, 60–70 — удовлетворительно**, 71–84 — хорошо, 85–100 — отлично | `backend/app/domain/analytics/config.py` (`DEFAULT_GRADE_BANDS`), переопределение на уровне дисциплины — `assessment_configurations.grade_bands` |
| A2 | Порог для экзамена с отдельной частью (тип C) при оценке риска во время семестра | «Безопасный» семестровый уровень S = 60 − 18 = **42** (с минимальными 18 на экзамене итог ≥ 60); «граница невозможности» F = 60 − 30 = **30** | `config.py` (параметры типа C) |
| A3 | Результат отсутствует у работы завершённого модуля | Это **«нет данных»**, а не ноль и не потенциал: снижает полноту, при > 50 % — «Недостаточно данных» | `config.py` (`insufficient_missing_share`) |
| A4 | Коэффициенты риска (доля остатка, разрыв темпа, надёжность темпа) | Стартовые значения 0.9 / 0.7 / 0.25 / 0.1 / 0.25 — эвристика, не статистическая модель; описана в `analytics-model.md` | `config.py` (`RiskParams`) |
| A5 | Индекс учебной устойчивости | Равные веса зон, ограничение сверху при critical (≤ 59) и high (≤ 74); называется «ориентировочным», не вероятностью | `config.py` (`IndexParams`) |
| A6 | Статусы заявок | Модель ТЗ + «Требуется уточнение», «Завершена», «Отозвана» — чтобы студент понимал, что делать дальше; у каждого статуса есть текст «что дальше» | `services/application_types.py` |
| A7 | «Связь с деканатом» | Реализована как тип заявки «Обращение в деканат» с перепиской; сотрудник отвечает из кабинета деканата | там же |
| A8 | Как жюри увидит смену статусов и пересчёт аналитики | Добавлен **кабинет сотрудника деканата** (отдельная роль): обработка заявок, ответы, просмотр успеваемости (только чтение), объявления. Выставление баллов деканатом убрано 22.11 по замечанию заказчика: баллы ставит преподаватель, деканат только смотрит | `api/staff.py` |
| A9 | Дата «сегодня» и демо-данные | Данные привязаны к осеннему семестру 2026/27; «сегодня» — реальная дата в часовом поясе Europe/Moscow. Для тестов и записи демо можно зафиксировать `DEMO_TODAY` | `.env` |
| A10 | Числитель/знаменатель | Неделя 1 начинается с понедельника 31.08.2026; нечётная неделя — числитель | `curriculum.json` (`week1_monday`) |
| A11 | Название вуза | По умолчанию нейтральное «Технический университет»; реальное название подставляется переменной `UNIVERSITY_NAME`. Официальный логотип не используется, на всех страницах — дисклеймер «концепт для конкурса» | `.env` |
| A12 | Демо-пароли | Публичные тестовые учётные данные для жюри, не секреты; в клиентском коде их нет; переопределяются переменными `DEMO_PASSWORD_*` при первом заполнении БД | `.env` |
| A13 | Учебные материалы | Каталог заранее проверенных открытых ссылок по темам (ТЗ §16.3 допускает для первой версии); архитектура позволяет подключить поиск/RAG | `seed/data/learning_resources.json` |
| A14 | Хранилище | SQLite в постоянном томе `/data` (достаточно для прототипа, бэкап — копия файла); PostgreSQL поддерживается через `DATABASE_URL` без изменений кода | `.env` |
| A15 | Электронные документы | Для заявок с электронной выдачей формируется печатная форма с водяным знаком «ОБРАЗЕЦ · КОНЦЕПТ» и кодом проверки — демонстрация идеи, не юридический документ | `api/meta.py` |
