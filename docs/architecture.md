# Архитектура

## Обзор
```
Браузер (телефон / ПК)
   │  HTTPS, один домен
   ▼
┌───────────────────────────── Docker-контейнер ─────────────────────────────┐
│ Uvicorn + FastAPI                                                           │
│  ├─ /api/*  ── REST API (JSON)                                              │
│  │    ├─ security/   сессии, CSRF, argon2id, роли, лимит попыток входа      │
│  │    ├─ api/        auth · student · applications · notifications · staff  │
│  │    ├─ services/   расписание · заявки · уведомления · адаптер аналитики  │
│  │    └─ domain/analytics/  чистый модуль расчётов (без БД и веба)          │
│  └─ /*      ── собранный SPA (React) + fallback на index.html               │
│ SQLAlchemy 2 + Alembic ─────► SQLite в томе /data  (или PostgreSQL)         │
└─────────────────────────────────────────────────────────────────────────────┘
```
- **Один процесс, один домен.** Frontend собирается в статические файлы и раздаётся тем же сервером, что и API:
  нет CORS, cookie сессии работает в режиме SameSite=Lax, деплой — один контейнер.
- **Frontend:** React 18 + TypeScript + Vite, React Router, TanStack Query (кэш и состояния загрузки),
  собственная дизайн-система на CSS-переменных, иконки lucide, шрифт Manrope (self-hosted, без CDN —
  приложение не зависит от внешних ресурсов, что важно для доступности из РФ).
- **Backend:** FastAPI (Python 3.12), SQLAlchemy 2, Alembic-миграции, Pydantic-валидация.
- **Аналитика** — отдельный детерминированный доменный модуль: вход — неизменяемые структуры, выход — структуры
  с объяснениями. Backend только собирает вход из БД (`services/academics.py`); формулы во frontend не дублируются.

## Почему такой стек
| Критерий ТЗ §5.1 | Решение |
|---|---|
| Скорость разработки | FastAPI + React — зрелые инструменты с предсказуемой генерацией кода ИИ |
| Надёжность | Строгая типизация (Pydantic, TypeScript strict), миграции, 1 контейнер |
| Тестирование | pytest (домен + API + безопасность), Playwright (сценарии, 360 px) |
| Безопасность | Серверные сессии, argon2id, CSRF-токен, проверка владельца на каждом запросе, CSP |
| Масштабирование | Stateless-сервер приложения; переход SQLite → PostgreSQL сменой `DATABASE_URL`; лимитер входа выносится в Redis |
| Сопровождение | Чёткие слои (api → services → domain), конфигурация правил отдельно от кода, документация в `docs/` |

## Слои backend
| Слой | Содержимое | Правило |
|---|---|---|
| `api/` | HTTP-эндпоинты, схемы запросов | Каждый защищённый эндпоинт получает `Principal` из сессии; ID пользователя из запроса не принимается |
| `services/` | Расписание из сетки + изменения, каталог заявок и переходы статусов, уведомления, адаптер аналитики | Доступ к данным студента — только через функции с фильтром по владельцу |
| `domain/analytics/` | Расчёты БРС, риск, цели, индекс, приоритеты, тексты | Чистые функции; конфигурация в `config.py`; 100 % детерминированность |
| `models.py` + `migrations/` | ORM и схема БД | Изменения схемы — только миграциями Alembic |
| `seed/` | Вымышленные демо-данные, каталог материалов | Заполнение пустой БД при старте; `python -m app.seed --reset` |

## Основные потоки
1. **Вход:** `POST /api/auth/login` → проверка argon2id → новая серверная сессия (в БД — SHA-256 токена) → HttpOnly-cookie + CSRF-токен в теле ответа (хранится в памяти SPA).
2. **Запрос данных:** cookie → сессия → пользователь → роль → выборка с условием `user_id = текущий` (или проверка записи на дисциплину).
3. **Аналитика:** `Enrollment` + модули + работы + результаты → `DisciplineInput` → `analyze_discipline()` → `summarize()` → JSON.
   Изменение баллов сотрудником сразу меняет результат (кэша нет — расчёт занимает миллисекунды).
4. **Заявка:** валидация полей по описанию типа → запись + история статусов → сотрудник меняет статус → уведомление студенту.
5. **Уведомления:** часть создаётся событиями (статусы, баллы, объявления), часть — идемпотентно из учебных данных
   (сроки ≤ 3 дней, изменения расписания ≤ 7 дней) по ключу `source_key`, без дублей.

## Расширяемость
- Новый тип справки — описание полей в `APPLICATION_TYPES`, без изменения кода форм (форма строится динамически).
- Новая схема аттестации или иные пороги — `AssessmentConfiguration` / `config.py`.
- Материалы: каталог → в перспективе поиск по открытым источникам или RAG по материалам курса (интерфейс `topic → resources` не меняется).
- Интеграции с реальными системами вуза **сознательно не подключены** (ТЗ §5.3 п.8).
