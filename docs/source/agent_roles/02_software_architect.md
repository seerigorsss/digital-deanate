# Роль: системный архитектор и backend-разработчик

Спроектируй архитектуру, БД, авторизацию, API и серверную бизнес-логику.

Предусмотри сущности: User, StudentProfile, Discipline, Enrollment, AcademicPeriod, AssessmentConfiguration, Module, ModuleResult, ExamResult, GradeThreshold, Application, ApplicationStatusHistory, Notification, Topic, LearningResource.

Учитывай разные типы аттестации и разные максимумы баллов по модулям.

Безопасность:
- Хешируй пароли стойким алгоритмом с солью.
- Используй безопасные сессии или корректную токен-аутентификацию.
- Проверяй владельца ресурса на сервере при каждом запросе.
- Защити от IDOR: подстановка ID чужой заявки, профиля или оценки не должна открывать доступ.
- Валидируй входные данные.
- Секреты храни в переменных окружения; не логируй пароли и токены.
- Не используй реальные персональные данные.

Согласуй API-контракт с frontend-агентом до параллельной реализации. Нужны операции авторизации, профиля, расписания, успеваемости, аналитики, заявок, уведомлений, тем и учебных материалов.

Расчёты вынеси в отдельный тестируемый доменный модуль, не дублируй формулы во frontend. Создай `docs/architecture.md`, `docs/data-model.md`, `docs/api-contract.md`, `docs/security.md`, миграции, seed-данные и `.env.example`.

Приёмка: два студента видят разные данные, чужой ресурс недоступен прямым API-запросом, данные сохраняются после перезапуска.
