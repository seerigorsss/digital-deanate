# Каталог учебных материалов по темам

Роль 05 («Исследователь и куратор учебных материалов»), ТЗ §16 и §18 п. 11–12.
Каталог: `backend/app/seed/data/learning_resources.json`. Дата проверки ссылок: **2026-11-21**.

## 1. Источник тем

Темы взяты из учебного плана прототипа `backend/app/seed/data/curriculum.json`: 14 дисциплин, 63 темы
(`disciplines[].topics[].key` / `title`). План вымышленный, но формулировки тем соответствуют типовым рабочим программам
технического вуза. Материалы подбирались **по формулировке конкретной темы**, а не по названию дисциплины. Например, для
`calc-triple-integrals` («…цилиндрические и сферические координаты») отдельно искали источник по сферическим координатам,
потому что основной урок покрывает только цилиндрические.

Каждая запись каталога содержит: `id`, `topic_keys` (одна или несколько тем), точное название, тип, источник,
автора (только если он виден на странице), URL, язык, краткое содержание своими словами, объяснение пользы для каждой
темы (`relevance`), сложность и длительность (только если их можно обосновать), `link_status`, дату проверки и условия доступа.

## 2. Критерии отбора

1. **Соответствие теме.** Страница должна раскрывать именно эту тему. Если она покрывает тему лишь частично, это прямо
   сказано в `relevance` (например, «сферические координаты не рассматриваются», «интегрирующий множитель не разбирается»).
2. **Легальность и открытость.** Брались страницы авторов и платформ, официальная документация, открытые учебники
   (CC BY / CC BY-NC-SA), материалы, которые вузы сами выложили на своих сайтах, в репозиториях и электронных библиотеках.
   Не брались: файлообменники, «скачать pdf», копии коммерческих учебников на сторонних сайтах, платные курсы.
3. **Язык.** По возможности русскоязычные источники. Англоязычные — для тем по английскому языку и там, где
   англоязычный открытый учебник заметно полезнее; язык указан в поле `language`.
4. **Доступность из РФ.** Видео на YouTube не использовались. Сервисы с известными блокировками или фильтрацией ботов
   (например, FreeCAD Wiki) исключены.
5. **Достоверность метаданных.** Название, автор, длительность и содержание взяты только с открытой страницы.
   Если автор не виден, `author = null`. `difficulty` задан только при явных признаках: «для чайников», «начальный уровень»
   или «для начинающих» — `basic`; вузовский конспект или учебное пособие с выводами — `intermediate`; углублённый
   учебник мехмата или пособие для технических университетов — `advanced`. Для энциклопедических статей и глоссариев
   сложность не указана (`null`).
6. **Объём:** 1–3 материала на тему.

## 3. Процесс поиска и проверки

1. **Поиск кандидатов** через WebSearch по формулировке темы, а также через оглавления известных открытых ресурсов:
   карта уроков МатПрофи, оглавление METANIT C++, список уроков AlexGyver, оглавление цикла лекций по ТАУ на Хабре,
   оглавления OpenStax и All About Circuits.
2. **Проверка каждого URL через WebFetch:** открылась ли страница (не 404, не заглушка), какие у неё точное название
   и автор, совпадает ли содержание с темой. Для PDF дополнительно сверялись титульный лист (название, авторы, вуз, год)
   и разделы, относящиеся к теме. Для крупных учебников проверялись конкретные главы и параграфы, указанные в `relevance`
   (например, §9, §14.4, §15.1, §18 в «Лекциях по дифференциальным уравнениям» ТПУ).
3. В каталог попали **только успешно проверенные ссылки**: у всех 142 записей `link_status = "verified"`.
   Неподтверждённые кандидаты не включались вовсе, поэтому статуса `unverified` в каталоге нет.
4. **Проблемы при проверке** (кандидаты, которые из-за них отброшены или заменены):
   - часть страниц ru.wikipedia.org инструмент проверки не открыл (`url_not_found`), хотя они есть в поиске:
     «Правила Кирхгофа», «Электромагнитная индукция», «Устойчивость по Ляпунову», «AVR», «Валовой внутренний продукт»,
     «Метод узловых потенциалов», «Метод комплексных амплитуд» и др. Они не включены и заменены другими источниками
     (OpenStax, БРЭ, вузовские PDF);
   - neerc.ifmo.ru и e-maxx.ru отвечали нестабильно (ошибки сервера, недоступный robots.txt). Повторно открыть
     страницы «ДНФ» и «Отношение связности, компоненты связности» не удалось, они не включены;
   - Хабр ограничивает частоту запросов, поэтому статьи проверялись по одной;
   - не открылись или заблокированы для автоматического доступа: FreeCAD Wiki (антибот-защита Anubis),
     pressbooks.bccampus.ca и opentextbc.ca (взята версия того же учебника на LibreTexts), feynmanlectures.caltech.edu,
     ctms.engin.umich.edu, rosstat.gov.ru, machinelearning.ru;
   - **отклонены по содержанию или лицензии:** платный курс Stepik «Английский язык для инженеров…»; курсы Stepik,
     программа которых не видна без JS-загрузки (нельзя подтвердить соответствие теме); учебник ТММ издательства
     ИНФРА-М на сайте стороннего вуза и глава коммерческого учебника на сайте экономфака (неясный статус лицензии).
5. **Ограничение проверки:** доступность проверялась из среды агента, а не из российской сети. Отсутствие блокировок
   в РФ предполагается по известной практике: Википедия, Хабр, Stepik, сайты вузов и OpenStax в РФ работают.
   Абсолютной гарантии это не даёт.

## 6. Как архитектура позволяет подключить поиск и RAG

1. **Стабильный контракт `topic → resources`.** UI и API (`GET /api/topics/{id}`) работают со связкой
   `topics` ↔ `learning_resources` через `topic_resources` с полем `relevance`. Источник записей — сейчас JSON-каталог
   из seed. Его можно заменить провайдером, не меняя ни фронтенд, ни формат карточки материала (ТЗ §16.2).
2. **Провайдеры за одним интерфейсом.** Логично выделить `ResourceProvider.find(topic) -> list[Resource]` с реализациями
   `CatalogProvider` (текущий JSON), `OpenSearchProvider` (поиск по открытым источникам: Википедия, OpenStax,
   репозитории вузов) и `CourseRagProvider` (материалы курса). Результаты объединяются и сортируются по релевантности.
   Записи каталога, проверенные куратором, всегда показываются первыми.
3. **Проверка ссылок как отдельный шаг.** Для найденных автоматически материалов действует тот же конвейер, что и при
   ручной проверке: открыть URL, сверить заголовок и содержание с темой, записать `link_status` и `checked_on`.
   В интерфейс попадают только `verified`, поэтому фиктивные рекомендации не отображаются (приёмка роли 05).
   Плановая перепроверка каталога ловит «умершие» ссылки.
4. **RAG по материалам курса.** Рабочие программы, конспекты и методички кафедры разбиваются на фрагменты,
   векторизуются и индексируются с метаданными `discipline_key`, `topic_key`, `source`. Запрос строится из формулировки
   темы и слабых модулей студента из аналитики. Ответ обязан цитировать конкретный фрагмент и ссылку на документ,
   так что сгенерированный текст не выдаётся за существующую публикацию.
5. **Пустая подборка — штатный случай.** Поле `topics_without_materials` и пустой список ресурсов у темы обрабатываются
   явно (ТЗ §18 п. 12): интерфейс честно сообщает, что материалов нет, и не подставляет «похожие».

## 7. Обновление каталога

- Новый материал добавляется, только если ссылка открыта и содержание сверено с темой. Указываются `checked_on` и
  `link_status: "verified"`, `id` — следующий свободный (`r143`, …).
- Каждый `topic_keys` должен существовать в `curriculum.json`. Проверка валидности:
  `python3 -I -c "import json;json.load(open('backend/app/seed/data/learning_resources.json'))"`.
- Перепроверять ссылки рекомендуется в начале каждого семестра. Недоступные записи нужно исключать или переводить
  в `unverified` с пояснением в `access_note`. Темы, оставшиеся без материалов, переносятся в `topics_without_materials`.
