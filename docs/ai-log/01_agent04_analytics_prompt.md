## Задача
Реализуй пакет `backend/app/domain/analytics/` — чистый, детерминированный, объяснимый модуль (без БД, FastAPI, ORM, сети, случайности, без чтения текущей даты внутри — дата приходит во входе):
- `types.py` — входные/выходные dataclass по контракту (`to_dict()` у выходных структур, JSON-сериализуемо, даты в ISO).
- `config.py` — ВСЕ пороги, шкала оценок (0–59/60–70/71–84/85–100), параметры типов аттестации, коэффициенты риска, веса/зоны индекса, веса приоритизации, `weak_module_share`. Комментарии к каждому параметру.
- `engine.py` (или несколько модулей) — `analyze_discipline(inp: DisciplineInput, cfg=DEFAULT_CONFIG) -> DisciplineAnalytics` и `summarize(items: list[DisciplineAnalytics], today: date, cfg=DEFAULT_CONFIG) -> AnalyticsSummary`.
- `texts.py` — генерация русских объяснений, причин и рекомендаций строго из вычисленных данных (шаблоны, без выдумывания заданий и сроков). Тон — объективный и поддерживающий, без запугивания; не называть уровень риска вероятностью.
- `__init__.py` — публичный API: `analyze_discipline`, `summarize`, типы, `DEFAULT_CONFIG`.

Тесты в `backend/tests/domain/`:
- все 12 случаев ТЗ §18 (каждый — отдельный тест с понятным именем);
- граничные: 59/60 для зачёта; 60/71/85 для распределённого экзамена при разном остатке; C: 70+18; need < 18 → требуется 18; need > 30 → недостижимо при текущих баллах (и достижимо при добранных семестровых, если остаток позволяет); экзамен сдан на 17 → critical, на 18 → допускается; нулевой остаток; ранний/поздний семестр; нет данных; одна критическая дисциплина при 6 зелёных → индекс ≤ 59 и `zone_counts.critical == 1`; пересчёт после изменения баллов меняет уровень/рекомендацию; валидация диапазонов;
- сценарный тест: загрузи `curriculum.json` + `demo_results.json`, построй входы (модули/работы из плана, баллы из demo_results, today=2026-11-23, semester_progress = доля дней между 2026-09-01 и 2026-12-27), проверь `expected_risk` по каждой дисциплине и `expected_index` (зона и значение ±1). Если твой алгоритм по контракту даёт другой результат — НЕ подгоняй данные молча: сначала перепроверь расчёт вручную; если расхождение в контракте или данных — опиши его в отчёте с числами.

Также создай `docs/analytics-model.md` — понятное человеку описание: три типа аттестации, допущение о границе 60, все формулы, классификация риска с примерами чисел, формула индекса и почему одна критическая дисциплина не прячется, приоритизация, ограничения (эвристика ≠ вероятность), таблица тестов (случай ТЗ → имя теста).
