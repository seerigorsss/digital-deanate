## Что сделать
### Архитектура
- `src/api/` — fetch-клиент: `credentials: 'same-origin'`, JSON, заголовок `X-CSRF-Token` для всех не-GET (токен из `/api/auth/me` или ответа логина, хранить только в памяти); единая обработка ошибок формата `{detail, code, errors}`; при 401 — переход на `/login?next=…`; при 403 `csrf_failed` — один раз перезапросить `/api/auth/me` и повторить. Типы в `src/api/types.ts`.
- Данные — через TanStack Query (кэш, повтор, инвалидация после мутаций). Никаких статических подставных данных.
- Маршрутизация (эти пути уже используются в ссылках уведомлений backend — реализуй именно их):
  - `/login`
  - `/` — главная
  - `/schedule` (`?date=YYYY-MM-DD`, переключатель «День / Неделя», навигация по неделям, кнопка «Сегодня»)
  - `/study` — «Академический радар»; вкладки через `?tab=radar|session|record` (Радар · Сессия · Зачётная книжка)
  - `/study/:disciplineId` — карточка дисциплины (+ «Что если»)
  - `/study/:disciplineId/topics/:topicId` — материалы по теме
  - `/applications` (фильтры Активные/Черновики/Завершённые/Все), `/applications/new` (`?type=<type_key>` открывает форму сразу), `/applications/:id`, `/applications/:id/document` (печатная электронная справка с водяным знаком «ОБРАЗЕЦ · КОНЦЕПТ…»)
  - `/notifications` (категории, непрочитанные, «Прочитать все», переход по `link`)
  - `/profile`, `/help` (FAQ из `/api/faq`)
  - Сотрудник: `/staff` (очередь заявок по статусам), `/staff/applications/:id` (смена статуса с комментарием из `allowed_transitions`, переписка), `/staff/grades` (выбор студента → дисциплины → работы, ввод/очистка баллов с мгновенным отображением нового уровня риска), `/staff/announcements` (форма объявления с аудиторией + список).
  - Студент, открывший `/staff/*`, и сотрудник, открывший студенческие страницы, перенаправляются в свой раздел. 404-страница для неизвестных путей.
- Навигация: на мобильных — нижняя панель (Главная, Расписание, Учёба, Заявки, Уведомления со счётчиком непрочитанных), шапка с логотипом и аватаром (меню: Профиль, Помощь, Выйти). На десктопе (≥ 1024 px) — левая боковая панель с теми же пунктами. У сотрудника — свой набор пунктов.

### Дизайн-система (`src/styles/` + `src/components/ui/`) и `docs/design-system.md`
Современный, цельный, «студенческий» стиль: светлый фон, карточки, мягкие тени, скругления, акцентный цвет (не копируй фирменный стиль вуза), шрифт Manrope (self-hosted через @fontsource, subsets latin+cyrillic, веса 400/500/600/700). CSS-переменные: цвета (включая семантику зон: красный — критический, оранжевый — высокий, жёлтый — внимание, зелёный — стабильно, серый — нет данных; контраст текста ≥ 4.5:1), отступы, радиусы, тени, типографическая шкала. Компоненты: Button (варианты, loading, disabled), Card, Badge/StatusPill, RiskBadge (цвет + иконка + текст — цвет никогда не единственный носитель смысла), Segmented/Tabs, поля формы с ошибками и подсказками, EmptyState, ErrorState (с «Повторить»), Skeleton, Toast, Modal/BottomSheet, Gauge (SVG-полукруг индекса), PointsBar (набрано / ещё можно / нет данных + отметки порогов), Avatar, PageHeader. Собственный логотип — простой SVG-знак (идея: «цифровой» деканат/шапка выпускника/радар), не копирующий логотип вуза. Опиши всё в `docs/design-system.md` (токены, компоненты, правила, лицензии шрифта и иконок).

### Экраны — содержание (главное)
- **Вход:** логин/пароль, показ пароля, понятная ошибка, блокировка кнопки при отправке, сообщение о лимите попыток. Под формой — подсказка с демо-логинами (только логины `student1`, `student2`, `dekanat`; **паролей в клиентском коде быть не должно**: «пароли — в инструкции для жюри»). Дисклеймер «Концепт для конкурса, не официальный сервис» (текст из `/api/meta`).
- **Главная** (по `/api/dashboard`): приветствие, дата и неделя (числитель/знаменатель); «Сегодня» — занятия с отметками изменений, либо пустое состояние «Сегодня занятий нет» + ближайшее занятие; карточка индекса (мини-шкала, зона, приоритет №1 со ссылкой); «Ближайшие сроки»; «Мои заявки» (статусы); последние уведомления; быстрые действия («Заказать справку», «Написать в деканат», «Успеваемость», «Расписание на неделю»).
- **Расписание:** день/неделя; карточки занятий: время, дисциплина, тип, аудитория, преподаватель; изменения визуально и текстом (отмена — зачёркнуто + «Отменено», перенос — откуда/куда, замена аудитории/преподавателя — старое → новое, доп. занятие — метка). Неделя на мобильном — список дней; на десктопе — колонки или список.
- **Академический радар** (`/api/analytics`): Gauge с индексом, подпись «ориентировочный индекс, не вероятность сдачи» + раскрываемое «Как считается» (`index.formula`); число дисциплин по зонам; объяснение; «Что подтянуть в первую очередь» (priorities: предмет, риск, причина, действие, срок); «Что идёт хорошо» (positives); список дисциплин по риску с PointsBar. Вкладки «Сессия» и «Зачётная книжка» — из `/api/grades` (средний балл, семестры, адаптивная таблица → карточки на мобильном).
- **Карточка дисциплины** (`/api/disciplines/:id`): тип аттестации, баллы и максимумы (текущие, максимум завершённых модулей, остаток, нет данных), PointsBar с отметками порогов; уровень риска с причинами; рекомендация; достижимость целей 60/71/85 (статус + сколько нужно и где); для экзамена — отдельный блок «Семестр + экзамен» с обязательным минимумом 18, итогом при 18 и при 30; модули со статусами и работами (оценено / ожидается / нет данных, сроки, просроченные); преподаватели; темы (слабые отмечены) → ссылки на материалы. **«Что если»**: для ожидаемых работ — поля ввода гипотетических баллов (и экзамена для типа «Экзамен»), кнопка «Пересчитать» → `POST /simulate`, показать новый риск/цели рядом с текущими, явно подписать «моделирование, ничего не сохраняется», «Сбросить».
- **Тема и материалы:** заголовок темы, модуль, отметка «стоит повторить», карточки материалов: название, тип, источник/автор, язык, краткое содержание, «почему рекомендовано», сложность/длительность если есть, статус проверки ссылки, кнопка «Открыть» (новая вкладка, `rel="noopener noreferrer"`). Пустое состояние — честное «материалы по этой теме пока не подобраны».
- **Заявки:** список с фильтрами и счётчиками, пустые состояния; создание: выбор типа (карточки с описанием и сроком) → динамическая форма по `fields` (text/textarea/number/select/date/discipline; клиентская валидация + показ серверных ошибок по полям) → «Отправить» или «Сохранить черновик» → экран подтверждения с номером и ссылкой на заявку. Карточка: статус, «что дальше» (`next_step`), данные заявки, таймлайн истории, переписка (отправка сообщения; при «Требуется уточнение» — заметный призыв ответить), действия по `permissions` (редактировать/отправить/удалить черновик, отозвать), ссылка на электронный документ, если `document_available`.
- **Уведомления:** категории-чипы со счётчиками, «Только непрочитанные», непрочитанные визуально выделены, клик — отмечает прочитанным и ведёт по `link`, «Прочитать все».
- **Профиль:** все поля профиля, университет, дисклеймер, выход.
- **Кабинет сотрудника:** см. маршруты выше; тот же визуальный язык.

### Обязательные качества (ТЗ §4, §5.4)
- Состояния: loading (скелетоны), empty, error (сеть/сервер с «Повторить»), success (toast/экран), validation, disabled, «нет результатов».
- Mobile-first: всё работает от **360 px**, нет горизонтальной прокрутки страницы, нет наложений, зоны касания ≥ 44 px, удобные формы; таблицы → карточки; графики читаемы.
- Доступность: семантическая разметка, label у полей, aria для иконок-кнопок, видимый фокус, `prefers-reduced-motion`, контраст.
- Никаких кнопок «в никуда», заглушек, `console.log`, ошибок в консоли браузера. TypeScript strict, `npm run build` без ошибок.
- На каждой странице (футер или под навигацией) — короткий дисклеймер «Концепт для конкурса · не официальный сервис».
