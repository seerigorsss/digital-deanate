## Этап 3. Backend (координатор)
- Реализованы модели (21 таблица), Alembic-миграция, серверные сессии (SHA-256 токена в БД), CSRF, argon2id,
  лимит попыток входа, роли, эндпоинты студента/заявок/уведомлений/деканата, сид.
- **Самопроверка до тестов нашла 2 дефекта** в собственном коде:
  1. история статусов и сообщения добавлялись через `db.add`, а ответ строился из уже загруженной коллекции —
     клиент получил бы устаревшую историю → переделано на `a.history.append(...)`;
  2. ключ идемпотентности уведомления строился как `len(a.history)` (мог совпасть у двух событий) → заменён на метку времени.
- Тесты: **24/24 прошли** (вход/выход, два профиля, генерический ответ на неверный пароль, лимит входа, недействительность
  cookie после выхода, флаги cookie, CSRF, argon2id в БД, разделение ролей, заголовки безопасности; IDOR для заявок —
  7 методов, дисциплин, тем, симуляции, уведомлений, подмена `user_id`, ссылка на чужую дисциплину в форме;
  жизненный цикл заявки, черновики, валидация, расписание с 5 видами изменений, главная, прочтение уведомлений,
  пересчёт аналитики после выставления баллов сотрудником, симуляция без сохранения).
- **Сверка аналитики с ручным расчётом:** фактические уровни и индексы (90 «Стабильно» / 51 «Высокий риск») совпали с эталоном.
- С работающего сервера сняты реальные ответы API → `docs/api-examples/` (контракт для frontend-агента).

## Этап 6. Проверка Docker-сборки (22.11, ~03:00)
- Демон Docker после перезапуска песочницы поднимался, но был остановлен вместе с фоновой задачей; по замечанию пользователя
  перезапущен и проверен (`docker info`), базовые образы оставались в кэше.
- Сборка 1: `pip` в контейнере не видит PyPI — контейнер не наследует сетевые настройки песочницы. Сборка 2 с `--network host`:
  `CERTIFICATE_VERIFY_FAILED` — прокси песочницы переподписывает TLS. **Решение:** в Dockerfile добавлен необязательный
  BuildKit-секрет `extra_ca` (корневой сертификат для сред с TLS-инспекцией); в образ не попадает, без него сборка обычная.
- Сборка 3: Python-этап и `npm ci` успешны; `npm run build` падает только из-за ещё не написанных frontend-агентом страниц — ожидаемо.
