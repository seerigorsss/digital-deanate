# Подача аналитики успеваемости (UX)

Как показывать индекс учебной устойчивости, зоны риска, причины, достижимость оценок, экзаменационный минимум 18, «недостаточно данных», критическую дисциплину и моделирование «Что если». Примеры формулировок для обоих демо-студентов посчитаны вручную по `docs/analytics-contract.md`.

**Граница ответственности.** Все расчёты, уровни, причины (`reasons`), объяснения (`explanation`) и рекомендации (`recommendation`) формирует доменный модуль backend (ТЗ §15.6, §17). Интерфейс их **показывает**, но не вычисляет пороги и не придумывает тексты. Формулировки ниже — эталон тона и структуры для `texts.py` и для статических подписей интерфейса.

---

## 1. Принципы

1. **Риск ≠ текущий балл.** Рядом с баллами всегда видны остаток («ещё можно набрать») и максимум к концу семестра. Низкий балл при большом остатке — не тревога.
2. **Сначала вывод, потом числа, потом подробности.** Метка риска → одна-две фразы «почему» → цифры → модули.
3. **Каждый цвет — с текстом и иконкой.** Ни одна зона не передаётся только цветом.
4. **Числа вместо оценочных слов.** «Нужно 40 из 60 оставшихся (67 %)», а не «нужно сильно постараться».
5. **Честность без запугивания.** Недостижимое называем недостижимым и сразу говорим, что можно сделать. Не обещаем результат.
6. **Нет вероятностей и прогнозов.** Индекс — «ориентировочный», уровень риска — эвристика. Слова «вероятность», «шанс», «прогноз сдачи» не используются.
7. **Нет данных — так и говорим.** «Недостаточно данных» — отдельное серое состояние, а не ноль и не красная зона.
8. **Хорошее тоже показываем.** На радаре всегда есть блок «Что идёт хорошо», если есть хоть одна стабильная дисциплина.

## 2. Словарь: поле контракта → подпись в интерфейсе

| Поле | Подпись | Пример | Где |
|---|---|---|---|
| `current_semester_points` / `semester_points_max` | «Набрано … из …» | «Набрано 42 из 70» | Карточка, список дисциплин |
| `remaining_points_max` | «Ещё можно набрать» | «Ещё можно набрать 20» | Карточка |
| `max_achievable_semester` | «Максимум к концу семестра» | «Максимум к концу семестра 62» | Карточка |
| `missing_points_max` (> 0) | «Не внесено» | «Не внесено 50 баллов за модуль 1» | Карточка, причина «нет данных» |
| `current_pace` (если `pace_is_reliable`) | «Темп по оценённым работам» | «Темп 84 % — 42 из 50» | Карточка |
| `projected_semester_points` | «Если сохранить текущий темп — около …» + «ориентир, не прогноз» | «около 59» | Только в шторке «Как это считается» |
| `required_share_of_remaining` | «… из … оставшихся (… %)» | «40 из 60 оставшихся (67 %)» | Цели, причины |
| `semester_target` (экзамен) | «Нужно в семестре, чтобы хватило минимальных 18 на экзамене» | «42» | Блок «Экзамен» |
| `exam.points_min` / `points_max` | «Экзамен: от 18 до 30, минимум 18 обязателен» | — | Блок «Экзамен» |
| `exam.total_at_exam_min` / `total_at_exam_max` | «Итог при текущих баллах: от … до …» | «от 54 до 66» | Коридор итога |
| `risk.level` / `risk.label` | Метка риска | «Средний риск» | Везде |
| `risk.reasons[]` | «Почему» (список) | — | Карточка, приоритеты |
| `targets[]` | «Цели» | «Хорошо (71): …» | Карточка |
| `next_actions[]` | «Что сделать» / «Ближайшие сроки» | «ДЗ 3 · до чт, 26 ноября · 10 баллов» | Карточка, Главная |
| `weak_topic_ids[]` / `topics[].is_weak` | «Стоит повторить» | — | Темы модуля в карточке, материалы |
| `data_completeness = partial` | «Часть баллов не внесена — оценка может измениться» | — | Карточка (под меткой риска) |
| `index.is_estimate` | «Ориентировочный индекс» | — | Радар, Главная |

## 3. Формулировки

| Используем | Не используем |
|---|---|
| «нужно», «можно», «стоит», «осталось», «ещё можно набрать» | «вероятность сдачи», «шанс», «прогноз», «вы не сдадите» |
| «недостижимо в этом семестре», «по баллам семестра закрыть не получится» | «провал», «завал», «катастрофа», «отчисление», «долг» |
| «ориентировочный индекс», «ориентир» | «объективная оценка», «официальный рейтинг» |
| «средний риск», «высокий риск», «критический риск» | «опасно», «срочно!», заглавные буквы, восклицательные знаки |
| «пока нельзя оценить», «недостаточно данных» | «0 баллов» для невнесённых результатов |
| «обсудите с преподавателем варианты» | «вам поставят пересдачу», «точно сдадите», «гарантированно» |

Обращение — на «вы», без фамильярности; в приветствии — только имя.

## 4. Индекс учебной устойчивости

### 4.1. Где и как

| Место | Компонент | Состав |
|---|---|---|
| Радар `/study` | Полукруглая шкала 0–100, 4 сегмента зон, маркер-стрелка, число крупно в центре | «90» · «из 100» · метка зоны «Стабильно» с иконкой · подпись «Ориентировочный индекс — не оценка и не вероятность сдачи» · ссылка «Как считается» |
| Главная | Горизонтальная мини-шкала с теми же сегментами и маркером | «Индекс учебной устойчивости» · «90 · Стабильно» · «ориентировочный» · чипы зон · приоритет №1 |
| Кабинет сотрудника | Число и метка зоны | «Индекс 90 · Стабильно» |

Сегменты шкалы (из конфигурации контракта): 0–49 «Критично» (красный), 50–64 «Высокий риск» (оранжевый), 65–79 «Требует внимания» (жёлтый), 80–100 «Стабильно» (зелёный). Сегменты разделены просветом 2 px; подписи границ (50, 65, 80) — мелким текстом под шкалой на радаре.

### 4.2. Счётчики зон — всегда рядом с индексом

Чипы — по уровням риска дисциплин (`zone_counts`), в порядке тяжести, только ненулевые: «Критический риск 1 · Высокий риск 3 · Средний риск 1 · Низкий риск 1 · Стабильно 1 · Нет данных 1». Каждый чип — иконка + текст + число, цвет уровня. На радаре нажатие фильтрует список дисциплин (`/study?zone=high`). Под чипами, если есть «Нет данных»: «Дисциплины без данных в индекс не входят».

### 4.3. Ограничение индекса критической дисциплиной

Backend заполняет `caps_applied` только когда ограничение действительно снизило значение (`uncapped_value` > `value`). Тогда под шкалой одна строка:
- `critical`: «Индекс не выше 59, пока есть дисциплина с критическим риском»;
- `high`: «Индекс не выше 74, пока есть дисциплины с высоким риском».

Если среднее и так ниже потолка (у Максима 50,7 < 59), строки нет — критическая дисциплина видна в чипах, в приоритете №1 и в объяснении. Так одна критическая дисциплина не теряется на фоне зелёных (ТЗ §15.7).

### 4.4. Шторка «Как считается индекс»

> **Индекс учебной устойчивости** — ориентировочный показатель от 0 до 100. Он помогает увидеть общую картину, но не является оценкой и не означает вероятность сдачи.
> Каждой дисциплине с известным уровнем риска даётся балл: «Стабильно» — 100, «Низкий риск» — 80, «Средний риск» — 60, «Высокий риск» — 35, «Критический риск» — 10. Индекс — среднее этих баллов, все дисциплины весят одинаково.
> Если есть дисциплина с критическим риском, индекс не выше 59; если есть «Высокий риск» — не выше 74. Дисциплины, по которым недостаточно данных, в расчёт не входят.
> *(Предложение)* **Ваш расчёт:** (4 × 100 + 80 + 60) / 6 = 90.
> Уровень риска дисциплины зависит не только от набранных баллов, но и от того, сколько ещё можно набрать, и от темпа по уже оценённым работам. Подробнее — в карточке каждой дисциплины.

Сейчас `index.formula` содержит только общую формулу — её и показываем. Строка «Ваш расчёт» появится, если backend добавит её в ответ; сам интерфейс индекс не пересчитывает. Зоны индекса (`index.label`) — «Стабильно», «Требует внимания», «Высокий риск», «Критично»; уровни дисциплин (`risk.label`) — «Стабильно», «Низкий риск», «Средний риск», «Высокий риск», «Критический риск», «Недостаточно данных». Это два разных словаря: зона — у индекса, уровень — у дисциплины.

### 4.5. Индекс не рассчитан

`index.value = null` (у всех дисциплин нет данных): шкала серая без маркера, вместо числа «—», текст «Индекс появится, когда преподаватели внесут первые баллы». Чип «Нет данных 7».

## 5. Уровни риска: метки, цвета, иконки

| `risk.level` | Метка (`risk.label`) | Цвет | Иконка (Lucide) | Что это значит для студента (подпись в «Как это считается») |
|---|---|---|---|---|
| `critical` | Критический риск | красный | `octagon-alert` | Порог в этом семестре уже недостижим или не выполнено обязательное условие (экзамен ниже 18) |
| `high` | Высокий риск | оранжевый | `triangle-alert` | Нужен почти весь остаток баллов или темп заметно выше текущего |
| `medium` | Средний риск | жёлтый (текст тёмный) | `circle-alert` | Сдать можно, но запас небольшой |
| `low` | Низкий риск | бирюзовый | `circle-check` (контур) | Сдать можно при реалистичном темпе |
| `stable` | Стабильно | зелёный | `shield-check` | Порог уже обеспечен или запас достаточный |
| `insufficient_data` | Недостаточно данных | серый | `hourglass` | Баллов пока слишком мало, чтобы оценить риск |

Правила:
- Метка — чип с иконкой и текстом; цветной фон чипа — светлый оттенок зоны, текст — тёмный оттенок той же зоны (токены — в `ux-brief.md`). Контраст текста ≥ 4,5:1.
- Карточка дисциплины не заливается цветом целиком: цвет только у чипа и узкой полосы слева у строки списка.
- Порядок в списках — по `disciplines[]` (backend сортирует по убыванию риска). Интерфейс порядок не меняет.
- Шесть уровней риска дисциплины сводятся к четырём зонам индекса только на шкале индекса; в списках и карточках показываются все шесть.
- Для экранного диктора чип читается полностью: «Уровень риска: средний риск».

## 6. Причины риска

Структура блока «Статус» в карточке дисциплины:
1. Чип уровня.
2. `explanation` — 1–3 предложения.
3. «Почему» — список `reasons` (1–3 пункта с числами).
4. Строка «Как это считается» → шторка с определениями: набрано, остаток, темп, уровни.

Эталонные шаблоны причин (для `texts.py`; числа подставляются из расчёта):

| Уровень / ситуация | Причина |
|---|---|
| `stable`, порог обеспечен (зачёт, распределённый) | «Набрано 62 из 100 — минимум для сдачи уже есть» |
| `stable`, порог обеспечен (экзамен) | «Семестровых баллов хватает: при 18 на экзамене итог будет не ниже 60. Сам экзамен нужно сдать минимум на 18» |
| `stable`, хороший запас | «До 60 нужно 16 из 50 оставшихся (32 %), а темп по оценённым работам — 88 %» |
| `low` | «Чтобы сдать с минимальными 18 на экзамене, нужно 12 из 25 оставшихся (48 %); текущий темп — 67 %» |
| `medium` | «Нужно 40 из 60 оставшихся (67 %), а темп по оценённым работам — 50 %» |
| `high`, почти весь остаток | «Нужен почти весь остаток: 24 из 25 баллов» |
| `high`, разрыв темпа | «Нужно набрать 80 % оставшихся баллов, а сейчас темп — 52 %» |
| `high`, экзамен выше минимума | «Семестр закрыт с 38 баллами: минимальных 18 на экзамене не хватит — для 60 понадобится 22» |
| `critical`, порог недостижим | «Набрано 27, оставшиеся работы дают ещё 30 — максимум 57, это меньше 60» |
| `critical`, экзамен ниже 18 | «Результат экзамена — 16, это ниже обязательного минимума 18» |
| `insufficient_data` | «Баллы за модуль 1 (50 баллов) ещё не внесены» |

## 7. Достижимость оценок («Цели»)

### 7.1. Что показываем по типу аттестации

| Тип | Цели | Визуализация баллов |
|---|---|---|
| Зачёт (A) | Одна: «Зачёт — 60» | Полоса 0–100, отметка 60 |
| Распределённый экзамен (B) | «Удовл. 60», «Хорошо 71», «Отлично 85» | Полоса 0–100, отметки 60/71/85 |
| Экзамен (C) | 60/71/85 по итогу «семестр + экзамен» | Полоса семестра 0–70 с отметками 30 и 42 + блок «Экзамен» с коридором итога |

Полоса баллов (одинаковая для всех типов): `[набрано — сплошной фирменный цвет][ещё можно набрать — штриховка][не внесено — пунктир][уже не набрать — светло-серый]`. Конец штриховки — «максимум к концу семестра». Подписи под полосой: «Набрано 20 · Ещё можно 60 · Максимум 80». Отметки порогов — тонкие вертикальные линии с подписью числа.

### 7.2. Статусы цели → текст

| `status` | Зачёт / распределённый | Экзамен |
|---|---|---|
| `reached` | Иконка `check` + «Уже набрано» (без цвета риска) | «Семестровых баллов хватает — на экзамене нужно не меньше 18» |
| `achievable` | «Нужно ещё 40 из 60 оставшихся (67 %)» + мини-полоса доли | «На экзамене нужно 24 из 30» или «Доберите 4 балла в семестре и сдайте экзамен на 30» (из `explanation`) |
| `unreachable` | «В этом семестре недостижимо: максимум — 80» | «Недостижимо: даже при максимуме в семестре и 30 на экзамене итог — 76» |
| `unknown` | «Пока нельзя оценить — не хватает данных» | то же |

Правило: при `insufficient_data` все цели — `unknown`; интерфейс никогда не пишет «недостижимо», если данных недостаточно.

### 7.3. Текущая оценка для распределённого экзамена

`current_grade` по текущей сумме в середине семестра может выглядеть как приговор: ООП у Анны — 57 из 100, это «неудовлетворительно» по шкале, хотя риск «Стабильно». Поэтому:
- пока остаток > 0 и сумма < 60 — метку `current_grade` не показываем; вместо неё цель «Удовл. 60: нужно ещё 3 из 35»;
- если сумма ≥ 60 — «Уже набрано на «удовлетворительно»» (или выше);
- когда все модули завершены — показываем итоговую оценку по шкале.

## 8. Экзамен с отдельной частью и минимум 18

Блок «Экзамен» в карточке (только тип C), сразу после «Баллов»:

```
Экзамен · чт, 14 января · ГУК 501
Обязательный минимум — 18 из 30. Без него экзамен не сдан, даже если сумма больше 60.

Итог при текущих 42 баллах семестра:
0 ──────────── 60 ───── 71 ───── 85 ───── 100
                [■■■■■■■■■■■■]
                60          72
   экзамен на 18 → 60        экзамен на 30 → 72
```

Правила:
1. **18 видно всегда** — в подзаголовке блока, в целях и в «Что если».
2. **Нужно меньше 18 → пишем 18.** Если для цели хватает 12 баллов, показываем «на экзамене нужно 18 (обязательный минимум)».
3. **Нужно больше 30 → недостижимо при текущих баллах**, и сразу путь: «Доберите N баллов в семестре и сдайте экзамен на 30» (если остаток позволяет).
4. **Коридор итога** `total_at_exam_min … total_at_exam_max` на шкале оценок. Если весь коридор ниже 60 — подпись: «Даже 30 на экзамене дадут 56 — нужно добрать баллы в семестре».
5. **Семестровая полоса 0–70** с двумя отметками: «30 — меньше этого не сдать даже с 30 на экзамене» и «42 — хватит минимальных 18 на экзамене».
6. **Экзамен сдан**: показываем итог и оценку; если результат < 18 — чип «Критический риск» и текст «Экзамен ниже обязательного минимума 18 — не сдан», сумму не называем оценкой.
7. Для типов A и B блока «Экзамен» нет; в типе аттестации пишем «Распределённый экзамен: все 100 баллов набираются в семестре, отдельного экзамена нет».

## 9. «Недостаточно данных»

| Где | Как |
|---|---|
| Список дисциплин | Серая полоса слева, чип «Недостаточно данных» с иконкой песочных часов, вместо баллов «баллы не внесены» |
| Карточка | Чип + текст: «Баллы за модуль 1 «Technical reading» (50 баллов) ещё не внесены. Оценим риск, когда они появятся. Если работы давно сданы — уточните у преподавателя». Цели — «Пока нельзя оценить». Ближайшие работы и сроки показываем как обычно |
| «Что если» | Кнопка неактивна: «Моделирование станет доступно, когда будут внесены баллы за прошедшие модули» |
| Индекс | Не участвует; подпись «Дисциплины без данных в индекс не входят» |
| Неполные данные (`data_completeness = partial`) | Риск показываем, под чипом — «Часть баллов не внесена (8 баллов) — оценка может измениться» |

Работы без результата в завершённых модулях помечаются в списке работ как «не внесено» (серым), а не «0».

## 10. Критическая дисциплина без запугивания

Структура карточки и приоритета: **факт → что это значит → что можно сделать → что ещё в порядке**.

Пример — ТММ у Максима (распределённый экзамен, 27 из 100, остаток 30):

> **Критический риск**
> 60 баллов в этом семестре уже не набрать: набрано 27, оставшиеся работы дают ещё 30 — максимум 57.
> Закрыть дисциплину в обычном порядке по баллам семестра не получится. Какие есть варианты — например, пересдача или индивидуальный график, — определяют преподаватель и деканат. С ними стоит поговорить как можно раньше.
> **Что сделать**
> • Обсудить варианты с преподавателем — Яковлев Сергей Михайлович, кафедра теории механизмов и машин.
> • Работы модуля 3 всё равно стоит выполнить (ДЗ 3 — до сб, 5 декабря; РК 3 — до чт, 17 декабря) и уточнить, как они будут учтены.
> [Написать в деканат] [Заявление на пересдачу или индивидуальный график]

Визуально: красный чип и узкая красная полоса слева; без красной заливки, мигания, восклицательных знаков и модальных предупреждений. На радаре рядом — «Что идёт хорошо», чтобы картина не была только негативной.

Не обещаем: «вам разрешат пересдачу», «баллы перенесутся». Не пишем: «вы провалили», «под угрозой отчисления».

## 11. «Что если»

**Назначение:** студент вводит гипотетические баллы за будущие работы (и результат экзамена для типа C) и видит пересчёт. Ничего не сохраняется.

**Поведение**
- Вход — кнопка «Что если…» в карточке дисциплины (подпись «Посчитайте, что будет при разных баллах»). На телефоне — нижняя шторка на 90 % высоты, на десктопе — правая панель 420 px. Адрес получает `#what-if`, «Назад» закрывает шторку.
- Сверху — плашка «Это моделирование — баллы не сохраняются и никому не видны».
- Блок результата — вверху шторки (виден при открытой клавиатуре): чип риска «было → стало», «Семестр: 42 из 70», цели, для экзамена — коридор итога или фактический итог.
- Ниже — поля по работам в состоянии «ожидается» (`state = pending`), по модулям: «ДЗ 3 · до вт, 1 декабря», поле «0–10», суффикс «из 10», чип «Максимум». Для типа C — поле «Экзамен · из 30 · минимум 18».
- Работы «не внесено» в моделировании не участвуют (подпись: «Работы с невнесёнными баллами не учитываются»).
- Пересчёт — запросом к backend без сохранения, через 400 мс после последнего ввода; во время запроса результат затемняется с подписью «Пересчитываем…». Интерфейс сам ничего не считает.
- Кнопки: «Сбросить» (очистить поля), «Готово» (закрыть). Закрытие сбрасывает значения.
- Валидация: целые числа от 0 до максимума работы; ошибка — «Введите целое число от 0 до 10»; неверное поле в пересчёт не отправляется.

**Тексты результата**
| Ситуация | Текст |
|---|---|
| Риск снизился | «Средний риск → Низкий риск. До 60 останется 20 из 35» |
| Риск не изменился | «Уровень риска не изменится: Высокий риск. Для 60 на экзамене понадобится 22 из 30» |
| Экзамен ниже 18 | «Экзамен не сдан: нужно не меньше 18 баллов, даже если сумма 72» |
| Цель недостижима даже при максимуме | «Даже при максимуме за оставшиеся работы — 57 из 100. До 60 не хватит 3 баллов» + кнопки «Написать в деканат», «Заявление на пересдачу или индивидуальный график» |
| Все работы оценены (A/B) | Кнопка неактивна: «Все работы оценены — моделировать нечего» |
| Ошибка | «Не удалось пересчитать. Введённые значения сохранены — попробуйте ещё раз» + «Повторить» |

## 12. Приоритеты и «Что идёт хорошо»

**«Что подтянуть в первую очередь»** (радар — 3 карточки и «Показать все (N)»; Главная — только №1):
- номер, дисциплина, чип риска;
- причина (`reason`) — одна строка;
- действие (`action`) — что сделать;
- ориентир (`points_target`) — «40 из 60 оставшихся до 60»;
- срок (`deadline`) — «до чт, 26 ноября · через 3 дня»; без срока — строка не показывается (сроки не придумываем);
- нажатие → карточка дисциплины.

Если приоритетов нет: «Сейчас ничего не требует срочного внимания. Ближайшие работы — в блоке «Ближайшие сроки» на Главной».

**«Что идёт хорошо»** (`positives`, до 3): дисциплина, зелёный или бирюзовый чип, короткая фраза («Набрано 41, до зачёта нужно 19 из 50 оставшихся, темп 82 %»). Дисциплина может одновременно быть в приоритетах (низкий риск с ближайшим сроком) — это допустимо, тексты разные. Если позитивов нет — блок скрывается (не пишем «ничего хорошего нет»).

## 13. Связь с темами и материалами

- В карточке дисциплины у модуля с долей ниже порога — метка «Слабый модуль · 36 %»; внутри модуля — его темы, слабые (`is_weak`) отмечены «Стоит повторить» с причиной «модуль 2: набрано 36 %». Отдельного экрана списка тем нет.
- Слабыми считаются и темы модуля, который ещё идёт, если по оценённым работам доля ниже порога (у дискретной математики — модуль 2: 4 из 10).
- На экране материалов — «Почему эта тема»: «В модуле 2 набрано 9 из 25 — эта тема входила в него» или «Тема текущего модуля: впереди ДЗ 3 (до 4 декабря)».
- Материал: «Почему рекомендовано» берётся из каталога (`relevance` по теме), статус ссылки — «Ссылка проверена 21.11.2026» или «Ссылка не проверена».
- Пустая подборка: «Для этой темы пока нет проверенных материалов. Мы не подставляем случайные ссылки. Спросите преподавателя или посмотрите соседние темы модуля».

## 17. Сверка с API и что остаётся согласовать

Сверено с `docs/api-examples/student1_analytics.json`, `student2_analytics.json`, `*_discipline_detail.json`: индексы (90 и 51), уровни, причины, приоритеты и позитивы совпадают с ручным расчётом раздела 14.

**Уже так в API (учесть во frontend):**
1. Метки уровней `risk.label`: «Критический риск», «Высокий риск», «Средний риск», «Низкий риск», «Стабильно», «Недостаточно данных»; зоны индекса `index.label`: «Стабильно», «Требует внимания», «Высокий риск», «Критично».
2. При нехватке данных цели приходят со `status = unknown` и текстом «Данных пока недостаточно, чтобы оценить достижимость».
3. `caps_applied` заполняется, только если потолок снизил значение (есть `uncapped_value`).
4. Слабые темы (`is_weak`) считаются и для идущего модуля с частично оценёнными работами.
5. «Что если» — `POST /api/disciplines/{id}/simulate` с `overrides[{item_id, points}]` и `exam_points`, без сохранения.

**Предложения backend (не блокируют frontend):**
1. `targets[].explanation` для экзамена при нужном экзамене выше 18 — добавлять путь через семестр: «На экзамене нужно 24 — или доберите 6 в семестре, тогда хватит минимальных 18». Сейчас текст «Семестровых баллов достаточно: на экзамене нужно не меньше 24 баллов» можно прочитать как «в семестре больше ничего не нужно».
2. `index.formula` — добавить строку с расчётом студента: «(4 × 100 + 80 + 60) / 6 = 90».
3. `current_grade` для распределённого экзамена приходит и в середине семестра (ООП: «Неудовлетворительно» при 57 из 100 и риске «Стабильно») — интерфейс скрывает эту метку, пока остаток > 0 (раздел 7.3).
