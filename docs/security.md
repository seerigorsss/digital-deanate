# Безопасность

Соответствие требованиям ТЗ §5.3 и роли 02/06.

| Требование | Реализация | Проверка |
|---|---|---|
| 1–3. Каждый видит только свои данные; доступ проверяется на сервере для каждого ресурса | Студенческие эндпоинты не принимают ID пользователя — он берётся из сессии. Заявки/уведомления выбираются с условием `user_id = текущий`; дисциплины и темы — через запись на дисциплину (`enrollments`). Чужой ресурс отвечает **404**, как несуществующий (не раскрывается факт существования). Роли `student`/`staff` разделены (403) | `tests/test_isolation.py` (IDOR: GET/PATCH/POST/DELETE чужой заявки, документ, сообщения, дисциплина, тема, симуляция, уведомление, подмена `user_id` в query, ссылка на чужую дисциплину в форме) |
| 4. Пароли — стойкий хеш с солью | **Argon2id** (`argon2-cffi`: t=3, m=64 МБ, p=2, соль 16 байт на каждый хеш); прозрачный rehash при смене параметров; выравнивание времени ответа для несуществующих логинов | `test_passwords_hashed_with_argon2`, `test_wrong_password_generic_error` |

## Сессии и CSRF
- Cookie `dd_session`: `HttpOnly`, `SameSite=Lax`, `Secure` (в production), `Path=/`; срок — 72 ч, бездействие — 12 ч.
- Выход удаляет сессию **на сервере**: старая cookie больше не работает (`test_session_token_invalid_after_logout`).
- При входе старая сессия из cookie уничтожается (защита от фиксации сессии).
- Все изменяющие запросы требуют заголовок `X-CSRF-Token`, совпадающий с токеном сессии (сравнение за постоянное время),
  и тело `application/json`. Кросс-сайтовая HTML-форма не может выполнить ни одно из условий (`test_csrf_required_for_mutations`).

## Прочие меры
- **Перебор паролей:** не более 10 попыток на пару IP+логин за 5 минут → 429 (`test_login_rate_limited`). Сообщение об ошибке входа одинаковое для неверного логина и пароля.
- **Валидация входа:** Pydantic-схемы для всех тел; поля заявок проверяются на сервере по описанию типа (типы, длины, диапазоны, списки значений, принадлежность дисциплины студенту); управляющие символы вычищаются; тело API ≤ 64 КБ.
- **Заголовки:** Content-Security-Policy (`default-src 'self'`, `frame-ancestors 'none'`), `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, HSTS при HTTPS, `Cache-Control: no-store` для API.
- **Ошибки:** единый JSON-формат без трассировок; необработанные исключения → 500 с нейтральным текстом.
- **Документация API** (`/api/docs`) отключена в production.
- **Контейнер:** приложение работает от непривилегированного пользователя `app` (entrypoint сбрасывает права после подготовки `/data`).
- **SQL-инъекции:** только параметризованные запросы SQLAlchemy.
- **XSS:** React экранирует вывод; пользовательский текст не вставляется как HTML; внешние ссылки открываются с `rel="noopener noreferrer"`.

## Известные ограничения прототипа
- Лимитер входа хранится в памяти процесса (при нескольких инстансах — вынести в Redis).
- Нет двухфакторной аутентификации и восстановления пароля (тестовые аккаунты выдаются жюри).
- Аудит-лог действий сотрудника хранится только как история статусов заявок и `graded_by_user_id` у баллов.
