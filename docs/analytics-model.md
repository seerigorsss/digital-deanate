# Модель академической аналитики

Описание алгоритма «Академического радара»: как считаются баллы, уровень риска,
цели по оценкам, индекс учебной устойчивости и приоритеты. Источник правил —
ТЗ §14–§18, интерфейс — `docs/analytics-contract.md`, допущения — `docs/assumptions.md`.

Код: `backend/app/domain/analytics/` — чистый Python без БД, FastAPI, сети и
случайности. Текущая дата не читается внутри модуля: она приходит во входе (`today`).
Один и тот же вход всегда даёт один и тот же результат.

| Файл | Что внутри |
|---|---|
| `types.py` | входные и выходные структуры (`to_dict()` → JSON) |
| `config.py` | **все** пороги, шкала, параметры типов аттестации, коэффициенты, веса, зоны |
| `validation.py` | проверка диапазонов входа |
| `metrics.py` | базовые величины (суммы, остаток, темп, S, F) |
| `risk.py` | классификация уровня риска |
| `targets.py` | цели 60/71/85, экзаменационная часть, текущая оценка |
| `texts.py` | русские причины, объяснения, рекомендации — только из вычисленных чисел |
| `engine.py` | `analyze_discipline()` |
| `summary.py` | `summarize()`: индекс, зоны, приоритеты, позитивные результаты |
| `materials.py` | отбор материалов каталога по конкретной теме (связка со слабыми темами) |

## 1. Главный принцип: эвристика, а не вероятность

Уровень риска и индекс — **объяснимые эвристики**: они показывают, какую долю
оставшихся баллов нужно набрать и насколько это расходится с текущим темпом.
Это **не** статистическая вероятность сдачи: модель не обучалась на исторических
данных и не может давать такие оценки. В текстах слова «вероятность» и «шанс» не
используются, индекс называется «ориентировочным».

## 2. Три типа аттестации

| Тип | Ключ | Семестр | Экзамен | Порог | Цели |
|---|---|---|---|---|---|
| A — зачёт | `credit` | 0–100 | — | ≥ 60 | «Зачёт» (60) |
| B — распределённый экзамен | `distributed_exam` | 0–100 | — | ≥ 60 | 60, 71, 85 |
| C — экзамен | `exam` | 0–70 | 18–30, **минимум 18 обязателен** | итог ≥ 60 и экзамен ≥ 18 | 60, 71, 85 по итогу |

Параметры типов — `ASSESSMENT_TYPE_DEFAULTS` в `config.py`; дисциплина может
переопределить их в своей `AssessmentConfig` (включая шкалу `grade_bands`).

### Шкала и допущение о границе 60

| Баллы | Оценка | Ключ |
|---:|---|---|
| 0–59 | Неудовлетворительно | `unsatisfactory` |
| 60–70 | Удовлетворительно | `satisfactory` |
| 71–84 | Хорошо | `good` |
| 85–100 | Отлично | `excellent` |

В исходной формулировке границы пересекаются на 60 («0–60 неуд» и «60–70 удовл»).
Для прототипа принято правило ТЗ §14.1: **60 — уже «удовлетворительно»**.
Оценка определяется по **нижней границе** диапазона (балл ≥ `min_points`), поэтому
дробные значения между диапазонами относятся к нижнему: 59,5 → «неуд.», 70,5 → «удовл.».
Границы задаются только в `DEFAULT_GRADE_BANDS` (`config.py`); другая трактовка —
это изменение конфигурации, а не кода (см. тест `test_custom_grade_bands_change_targets`).

## 3. Входные данные и их смысл

Дисциплина → модули (статус `completed | in_progress | upcoming`) → работы
(`max_points`, `due_date`, `points`).

| Ситуация | Состояние работы | Трактовка |
|---|---|---|
| `points` задан | `graded` | баллы набраны |
| `points = None`, модуль не завершён | `pending` | работа впереди → **оставшийся потенциал** |
| `points = None`, модуль завершён | `missing` | **нет данных** — не ноль и не потенциал |

`semester_progress` — доля прошедшего учебного периода (0..1) или `None`, если неизвестна.

## 4. Базовые величины (`metrics.py`)

```
current      = Σ points           по работам с результатом
graded_max   = Σ max_points       по работам с результатом
completed_max= Σ max_points       по работам завершённых модулей
remaining    = Σ max_points       по работам без результата в незавершённых модулях
missing      = Σ max_points       по работам без результата в завершённых модулях
max_achievable = current + remaining
pace         = current / graded_max                  (None, если graded_max = 0)
pace_is_reliable = graded_max ≥ min_evidence_share · semester_points_max   (0.25)
projection   = current + pace · remaining            (только если темп надёжен и этап семестра известен)
```

`projection` — ориентир «если продолжать в том же темпе», не прогноз; в текстах
округляется до целого («около 88»), чтобы не создавать ложной точности.

### Целевой семестровый уровень S и порог невозможности F

| Тип | S (риск «не сдать») | F (ниже — недостижимо) |
|---|---|---|
| A, B | 60 | 60 |
| C | 60 − 18 = **42** (при минимальных 18 на экзамене итог 60) | 60 − 30 = **30** (ниже — не сдать даже с 30) |

Дефицит `D = max(0, S − current)`, требуемая доля остатка `r = D / remaining`.

## 5. Уровень риска (`risk.py`)

Правила проверяются **по порядку**, срабатывает первое. Код правила отдаётся в
`risk.rule`, причины (1–3 фразы с числами) — в `risk.reasons`.

| № | Условие | Уровень | `pass_status` | `rule` |
|---|---|---|---|---|
| 1 | нет модулей/работ | insufficient_data | unknown | `no_items` |
| 1 | ничего не оценено (`graded_max = 0`) | insufficient_data | unknown | `no_graded` |
| 1 | `missing > 0.5 · completed_max` | insufficient_data | unknown | `missing_data` |
| 2 | C, экзамен сдан, экзамен < 18 | **critical** | failed | `exam_below_minimum` |
| 2 | C, экзамен ≥ 18, итог ≥ 60 | stable | passed | `exam_passed` |
| 2 | C, экзамен ≥ 18, итог < 60 | critical | failed | `exam_total_below_threshold` |
| 3 | `current ≥ S` | stable | secured | `semester_secured` |
| 4 | `max_achievable < F` | critical | unreachable | `unreachable` |
| 5 | C и `max_achievable < S` | high | achievable | `exam_above_minimum_required` |
| 6 | `r ≥ 0.9` | high | achievable | `almost_all_remaining` |
| 6 | темп надёжен и `r − pace ≥ 0.25` | high | achievable | `pace_gap_high` |
| 6 | `r ≥ 0.7` | medium | achievable | `limited_margin` |
| 6 | темп надёжен и `r − pace ≥ 0.1` | medium | achievable | `pace_gap_medium` |
| 6 | темп надёжен, `projection ≥ S + 0.1 · semester_max`, `r ≤ 0.5` | stable | achievable | `projection_margin` |
| 6 | иначе | low | achievable | `realistic` |

Пункт 6 при `remaining = 0` защищён веткой `no_remaining` (critical) — на практике
это уже покрыто пунктами 4–5.

**Почему ранний низкий балл не даёт critical (ТЗ §18 п.6).** Пока оценено меньше 25 %
семестрового максимума, темп считается ненадёжным, и уровень определяется только
долей остатка. Пример (B): первый модуль 6/20 (30 %), впереди 80 → D = 54, r = 0,675 → **low**.

**Почему поздний низкий балл повышает риск (п.7).** Тот же темп 55 %:
рано — 11/20, остаток 80, r = 0,61 → low; поздно — 48,4/88, остаток 12, r = 0,97 → **high**;
ещё позже — 49,5/90, остаток 10, максимум 59,5 < 60 → **critical**.

### Примеры на демо-данных (today = 2026-11-23)

| Дисциплина | Тип | Баллы | Остаток | Расчёт | Уровень |
|---|---|---|---|---|---|
| Матанализ | C | 42 / 50 | 20 | current = 42 ≥ S = 42 | stable (secured) |
| Дифф. уравнения | C | 36 / 45 | 25 | r = 6/25 = 0,24; темп 0,8; ориентир 56 ≥ 49 | stable |
| Физика | C | 30 / 45 | 25 | r = 0,48; темп 0,67; ориентир 46,7 < 49 | low |
| Дискретная математика | B | 20 / 40 | 60 | r = 0,67; темп 0,5; разрыв 0,17 ≥ 0,1 | medium |
| ТАУ | C | 26 / 50 | 20 | r = 0,8; темп 0,52; разрыв 0,28 ≥ 0,25 | high |
| ТВиМС | C | 18 / 45 | 25 | r = 24/25 = 0,96 ≥ 0,9 | high |
| ТММ | B | 27 / 70 | 30 | max = 57 < 60 | critical (unreachable) |
| Английский | A | — | 50 | ничего не оценено, 3 работы без баллов | insufficient_data |

## 6. Цели по оценкам (`targets.py`)

**A, B.** `need = T − current`: `need ≤ 0` → `reached`; `need ≤ remaining` → `achievable`
(`required_share_of_remaining = need / remaining`); иначе → `unreachable`.

**C (ТЗ §15.5).** Итог = семестр + экзамен.

```
need = T − current
если need ≤ 30:  exam_points_needed = max(18, need)       — хватает экзамена
если need > 30:  при текущих баллах недостижимо (reachable_with_current_points = false)
                 extra = T − 30 − current                  — добрать в семестре
                 extra ≤ remaining → achievable («добрать extra и сдать экзамен на 30»)
                 иначе            → unreachable
всегда: total_at_exam_min = current + 18, total_at_exam_max = current + 30
```

Примеры: семестр 55 → для 60 по сумме хватило бы 5, но требуется **18**
(итог 73); семестр 40, остаток 20 → для 85 нужно 45 > 30: «недостижимо даже с 30,
нужно добрать 15 и сдать экзамен на 30»; семестр 70 + экзамен 18 → итог 88, «Отлично».

До экзамена цели типа C имеют статус `achievable`, а не `reached`: итоговая оценка
не может считаться полученной, пока не выполнен экзаменационный минимум.
После экзамена: `reached`, если экзамен ≥ 18 и итог ≥ T; иначе `unreachable`.

`current_grade`: для B — по текущей сумме (это фиксация «сейчас», не прогноз);
для C после экзамена — по итогу (экзамен < 18 → «неудовлетворительно»); иначе `null`.

## 7. Полнота данных

* `insufficient` — уровень `insufficient_data`;
* `partial` — есть `data_issues`: сумма максимумов работ ≠ `semester_points_max`,
  есть работы без баллов в завершённых модулях, неизвестен этап семестра;
* `full` — иначе.

Нарушение диапазонов (баллы вне [0, max], экзамен вне [0, 30], `max_points ≤ 0`,
NaN, неизвестный тип, `semester_progress` вне [0, 1], пересекающаяся шкала,
повтор id) — ошибка входа: `AnalyticsInputError` (подкласс `ValueError`) со
списком всех нарушений; проверить заранее можно через `validate_discipline_input()`.

## 8. Индекс учебной устойчивости (`summary.py`)

```
балл уровня: stable 100, low 80, medium 60, high 35, critical 10   (insufficient_data — не учитывается)
среднее    = Σ баллов / число дисциплин с известным риском          (веса равные)
значение   = округление половины вверх
ограничения: есть critical → не выше 59; есть high → не выше 74
зоны: ≥ 80 «Стабильно», 65–79 «Требует внимания», 50–64 «Высокий риск», < 50 «Критично»
```

**Почему одна критическая дисциплина не прячется.** Без ограничения 6 стабильных
и 1 критическая дали бы (6·100 + 10)/7 ≈ 87 — зелёная зона. Ограничение сверху
опускает индекс до **59** («Высокий риск»), в `caps_applied` попадает `critical`,
а `zone_counts.critical = 1` показывается рядом с индексом. Кроме того, дисциплины
сортируются по убыванию риска, и критическая всегда первая в приоритетах.

`caps_applied` перечисляет только ограничения, которые реально снизили значение;
`uncapped_value` — среднее до ограничений (для прозрачности). Если все дисциплины
`insufficient_data`, `value = null`.

Демо: студент 1 — (100+100+80+100+60+100)/6 = **90**, «Стабильно»;
студент 2 — (35+35+35+10+80+60+100)/7 = 50,7 → **51**, «Высокий риск».

## 9. Приоритизация «Что подтянуть в первую очередь»

В список попадают дисциплины `critical`, `high`, `medium`, `low`.

```
score = вес риска (critical 1000, high 700, medium 400, low 100)
      + срочность: ближайший срок из next_actions;
          ≤ 3 дней или просрочено → 100; ≥ 30 дней → 0; между — линейно: 100·(30 − d)/27;
          срока нет → 0
      + достижимость: +50, если остаток > 0 и порог ещё достижим (pass_status = achievable)
```

Задания и сроки берутся **только** из `next_actions` (работы учебного плана без
результата в незавершённых модулях, по возрастанию срока, до 3 штук). Если порог
недостижим или экзамен не сдан — рекомендация обратиться к преподавателю или в
деканат (обсудить пересдачу/индивидуальный график), срок не указывается, результат
не обещается.

**Позитивные результаты** — дисциплины `stable` и `low` с ориентиром по темпу не ниже S.

## 10. Слабые темы и материалы

Модуль «слабый», если доля набранного по его оценённым работам < `weak_module_share`
(0,6). Его темы попадают в `weak_topic_ids`. `materials.py` отбирает из готового
каталога материалы, у которых тема указана **явно** (не по названию дисциплины),
скрывает недоступные ссылки (`broken`), ставит проверенные первыми и честно сообщает,
если материалов нет. Сам каталог и проверка ссылок — зона модуля материалов.

## 11. Тексты

Причины, объяснения и рекомендации собираются по шаблонам из чисел расчёта:
баллы, пороги, названия работ, модулей и сроков из учебного плана. Числа — с
десятичной запятой и правильными падежами («21 балл», «до 21 балла»). Тон —
объективный и поддерживающий: без слов «провал», «отчисление», «вероятность», «шанс».

## 13. Уточнения относительно контракта

1. **`min_evidence_share`** в контракте не задан — взято 0,25 (A4 в `assumptions.md`).
   Демо-результаты совпадают при любом значении в (0; 0,4].
2. **Цели типа C до экзамена — `achievable`, а не `reached`** (в примере контракта —
   `reached` при семестре 42). Приоритет у ТЗ §14.2/§15.5: итог не считается полученным,
   пока не выполнен минимум 18. Что семестровой части хватает, видно по
   `points_needed_semester = 0` и `reachable_with_current_points = true`.
3. **Неизвестный этап семестра** (`semester_progress = None`): ориентир по темпу
   (`projection`) не строится, ветка stable-по-темпу отключается, в `data_issues`
   добавляется пояснение, полнота — `partial` (ТЗ §15.5: «не делай вид, что можешь
   точно спрогнозировать итог»).
4. **Дополнительные поля** (только добавлены, контрактные не менялись): `as_of`,
   `semester_points_needed`, `risk.rule`, `modules[].is_weak`, `modules[].topic_ids`,
   `next_actions[].kind/module_id`, `targets[].reachable_with_current_points`,
   `exam.final_total`, `exam.total_max_possible`, `index.uncapped_value`,
   `index.disciplines_counted`, `priorities[].risk_label`.
5. **`current_grade` для C после экзамена** — по итогу (в контракте `null` для всех,
   кроме B). `exam.passed` — выполнен ли минимум 18 на экзамене; общий итог — в `pass_status`.
6. После экзамена `semester_points_needed` и `required_share_of_remaining` — `null`.

## 14. Ограничения

* Коэффициенты подобраны экспертно, а не по историческим данным; это не вероятность.
* Темп считается по всем оценённым работам одинаково, без учёта их сложности и вида.
* Ориентир по темпу предполагает, что следующие работы будут оценены так же, как прошлые.
* Пересдачи, бонусные баллы, «автоматы» и индивидуальные условия дисциплин не моделируются.
* Если сумма максимумов работ не совпадает с максимумом семестра, расчёт ведётся по
  фактическим работам, а расхождение показывается в `data_issues`.
* `current_grade` для B в середине семестра отражает только текущую сумму; интерфейсу
  стоит подписывать её как «по текущим баллам».
